---
name: Immersive evidence requirements
description: User requirements for the immersive extension without replacing existing product flows
---
Extend the existing explorer, never rebuild it or remove its map, paid access, generation, approval, independent review or Visual Build. The user explicitly requests finishing the initial build before adding immersion.

**Why:** “Immersion must never replace accuracy.”

**How to apply:** Genuine authorized panoramas alone permit a 360 mode, using an established viewer. Approved ordinary media permits an honestly labeled photo journey, never a reconstructed location. With neither, retain the traditional evidence view. Missing real panoramas/video block those acceptance tests, not permission to invent content.

Hotspots must reference actual database evidence and be confirmed in organization review; AI suggestions are never automatically approved. Use white/silver hotspots, monochrome interface, original media colors and existing vermilion brand accents.

**Why:** “Each hotspot must correspond to an actual documented project claim or media item.”

**How to apply:** Expose source, date, organization, project, evidence status and limitations. Before/after requires dated comparison evidence. Donation-date highlights use publication dates and the wording “Here's what this organization has reported since you last gave.” Do not imply financial attribution without legitimate allocation records. Preserve an always-visible map return, reduced motion, keyboard/list alternatives and mobile bottom-sheet evidence.

The user directed “use public data” for viewer verification when asked for organization-authorized media and permission records.

**Why:** Real, explicitly reusable public files can establish browser behavior without waiting for a participating organization; they cannot establish that organization's spatial or project claims.

**How to apply:** Verify reuse terms at the original source, retain credits and dates, and keep unrelated public media isolated from donor projects. Report public-media rendering separately from organization-confirmed hotspots and end-to-end project acceptance.

Republishing unchanged evidence must not count it as newly reported. Unknown historical publication dates must stay unknown rather than being inferred from event dates or the latest page publication.

**Why:** Otherwise routine draft edits or republishing would falsely imply new reporting since a donor's gift.

**How to apply:** Preserve the earliest known publication for unchanged source-backed content even when storage identifiers change. Explain first-publication filtering separately from recorded/as-of dates; exclude unknown dates from “since” results.

Keep reported-entry-date exploration separate from the donation-date filter.

**Why:** Financial evidence may need transaction/as-of date exploration, but those dates do not establish when donors could first see a report.

**How to apply:** Label the two filters separately and compose them when both are set. Preserve public-data demonstration disclosures and financial classifications alongside the immersive viewer.

Donor-side photographs, video and immersive exploration are the user's highest product priority. Continue using public data; urgency does not waive media permissions or evidence relevance.

**Why:** The user explicitly emphasized this priority and answered “use public data” when asked for authorized uploads.

**How to apply:** Distinguish official historical contextual reporting from evidence of a particular IATI activity. Never use unrelated geographic photos to fill an empty project gallery. Keep those limitations visible.
